# History implementation validation

Validated on Linux on 2026-09-20.

- `cargo test --locked --workspace`: 80 tests passed; the credentialed Microsoft live test remains ignored.
- `cargo clippy --locked --workspace --all-targets -- -D warnings`: passed.
- `cargo fmt --all -- --check`: passed.

The locked `rusqlite` 0.40.2 / `libsqlite3-sys` 0.38.2 dependencies bundle SQLite 3.53.2, which includes the upstream [WAL-reset concurrency fix](https://www.sqlite.org/wal.html#walresetbug). A regression check requires the linked SQLite version to be at least 3.51.3; it failed against the previous bundled 3.51.1 and passes after the upgrade. This guards the dependency requirement rather than attempting to reproduce the rare upstream race. The history schema is unchanged, so existing databases need no migration.

History tests cover immutable start/outcome events, complete results, repeated attempts, Unicode and literal search, local-day boundaries across DST, stable paging in both directions, concurrent first launches and writers, lock contention, unsupported schemas, corrupt databases, and storage failure warnings. Subprocess tests verify that SIGINT records cancellation and hard termination leaves an unfinished attempt. CLI tests use isolated application directories and verify that history remains readable without configuration or provider setup.

TUI tests cover editing and shortcut isolation, Neo Noted aliases and pane directions, draft preservation during previews and filtering, stale completions, and rendering at wide, stacked, compact, and minimum sizes. Profile tests cover first-launch installation, preserving existing edits, and resolving paths beside the effective config file.

A manual session with the Neo Noted profile and installed WikDict data successfully looked up `Verbindlichkeit`, opened History, filtered for `verbindlich`, selected a translation with `n`, and copied it with `yy` to the local desktop clipboard. The lookup produced exactly one start and one outcome event. A separate PTY smoke check resized the TUI through 120×32, 80×24, 40×18, 8×3, and back to 120×32, then verified normal exit restored both terminal attributes and the alternate screen.

The updated Excalidraw draft was exported and visually inspected; its editable source and PNG now describe start/outcome events and unfinished attempts. The original TUI snapshot remains the comparison baseline.

macOS and Windows execution and native clipboard behavior were not verified locally; the existing CI matrix covers those platforms. The optional Microsoft live test was not run. The pitch's review of applicable Microsoft retention terms remains a release follow-up; these checks do not establish permission for long-term storage of Microsoft results.

The input-mode follow-up was checked with the Neo Noted profile in a herdr pane using a temporary config and `[history].database = "session.db"`. Enter changed normal input to insert mode, visual selection copied/cut text through the native clipboard, `p` pasted at the cursor, and filter inputs used the same modes. Repeated directional pane moves stayed in PANE mode until explicitly toggled off. Only the submitted lookup wrote events; editing, copying, and filtering left the isolated database at one start and one outcome. Tests also cover clipboard failures, multiline rejection, Unicode selection, config-relative database paths, CLI overrides, the new `voci.db` default, and explicit access to preserved legacy files.

The shared single-line editor now lives in `src/tui/input.rs`. Word-motion tests cover normal, visual, and insert modes, both lookup and filter fields, punctuation, whitespace, accented graphemes, emoji, field boundaries, and the Neo Noted `b` context override. Both `d` and `x` are tested against selections and individual graphemes, including clipboard failure before mutation and pasting the cut text back.

A PTY smoke check verified the actual cursor-control sequences: steady I-beam in insert mode, steady block in normal/visual modes, and terminal-default restoration on exit. It exercised Ctrl-arrow and `b`/`e` motions, native clipboard cut/paste, and mode transitions in both lookup and filter inputs. Terminal attributes and the alternate screen were restored, and the temporary database was never created because no lookup was submitted.

The edtui 0.11.7 migration uses its buffer, mode/selection state, and editing actions for both lookup and filter inputs. Existing Unicode, clipboard-failure, configurable-binding, and cursor-style regressions pass. A new regression verifies that Enter exits pane mode without submitting a lookup, applying/closing the filter, entering insert mode, or changing the chosen control. The filter now shares Lookup's bordered input renderer and focus styling; its Text, Date, Apply, Clear, and Cancel controls render at all supported test sizes.

A herdr session with an isolated config/database path verified the new filter layout, Unicode draft display, Neo pane navigation, and Enter leaving pane mode with the dialog and draft intact. The PTY check again passed native cut/paste and cursor/terminal restoration; no default database was used. edtui's optional features remain disabled. Voci adapts edtui's scalar offsets to whole graphemes and retains its small grapheme-aware viewport because edtui 0.11's own scrolling measures individual scalar widths.

Normal-mode `a` now appends after the current grapheme and enters insert mode in lookup and filter fields. Tests cover both presets, a remapped `append` action, ordinary typing after activation, empty/end-of-field positions, combining accents, emoji, and subsequent submit/apply behavior. Workspace tests, Clippy, and formatting checks pass.

Normal-mode `u` undo and `Ctrl-r` redo use edtui snapshots in both inputs. Regression tests cover grouped insert sessions (including backspace), atomic visual replacements and cuts, Unicode cursor restoration, clean filter baselines, 100-step bounds, discarded redo branches, clipboard failures, configured aliases, and history-list refresh retaining Ctrl-r. The adapter supplies transaction grouping and gates stale upstream redo entries. Workspace tests, Clippy, formatting, and an isolated PTY check of native cut/paste followed by undo/redo passed; no database was created during the smoke check.

Visual-mode `c` (`change_selection`) now copies the selection, cuts it, and enters insert mode after successful clipboard copying. Tests cover both input fields, QWERTY/Neo presets, remapping, forward/reverse Unicode selections, empty selections, clipboard failures, insert-mode typing, and undo/redo treating the cut plus replacement as one change. All workspace tests, Clippy, and formatting pass. An isolated PTY check verified native clipboard change/paste, the immediate I-beam cursor transition, and undo/redo without creating a database.

The branch-review fixes were validated on Linux with 91 passing workspace tests and the credentialed Microsoft live test still ignored. Long translation candidates now render in a line viewport and remain reachable through their final line at wide and narrow sizes, including after resizing; copying retains the complete candidate. Insert inputs and filter controls execute command sequences through the shared resolver, with tests for modified prefixes, ordinary-letter suffixes, timeout, Escape, context changes, and typing isolation.

An isolated PTY session opened saved History with an invalid provider configuration, submitted a lookup using `Ctrl-x Ctrl-s`, verified its recorded configuration failure, applied a filter using the same sequence, and exited with terminal attributes restored. Browsing and filtering created no extra encounters. Unit tests exercise stale history responses, preserved selection, paging boundaries, recent preview updates, and recovery after read errors. Misses retain their known language pairs, and older outcome JSON remains readable without migration.

Successful provider preparation is shared lazily across shell submissions. A regression verifies that failed preparation can be retried and successful preparation is reused by coordinator clones. A synthetic Linux debug benchmark using already-indexed fixture dictionaries measured 500 local lookups at about 242 ms when preparing on every submission and 93 ms when reusing preparation. These timings quantify fixture setup overhead, not production performance. Formatting and workspace Clippy passed.

The details-scrolling follow-up separates the selected candidate from the viewport offset. Selection moves through the pane before scrolling at roughly 70% when moving down and 30% when moving up; reversing direction keeps the viewport still until the opposite margin is reached. Scrolling clamps at both ends. Rendered-row tests cover live Lookup, recent saved previews, and History details, including short lists, page movement, resizing, and beginning/end boundaries. Oversized translations remain readable line by line and copy as complete values. All 27 TUI tests, formatting, and workspace Clippy passed.
